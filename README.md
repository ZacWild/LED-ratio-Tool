## 本版（1.0.1）改了什么

这一版**没有新功能、没动计算结果**，只做了几处让工具**更好用**的修正：

- **触屏更好点**：24 个按钮（步进、开关、复制、分段选项等）的可点区域都加大到至少 36×36 px，手指粗或用触控笔也不容易点偏；按钮**看起来和原来一样大**。

## 0. 为什么会有这个工具

作者本人**不是开发者**。做这个工具的起因很实际：作者做 VJ（现场视觉）后期，在**启动仪式、开幕式**等大型活动的特定环节里，经常需要让视频画面**精确匹配 LED 大屏的真实物理尺寸和面积**——屏实际是 14 米 × 4 米还是其他异形尺寸，后期画布就要照着这个真实比例来；差一点，现场就是露黑边、画面变形或者被硬拉变形。

现成的比例计算器，要么只给一个数字（不管视频画布该做多大），要么太重（装在软件里的插件，现场临时算个数反而绕）。作者需要的很简单：**量一块屏的物理尺寸 → 直接知道该用多大的画布、误差多少、是裁还是留边**。这个工具就是照着这个念头做出来的。

- **谁在用**：VJ 后期、活动影像、舞台视觉、LED 现场技术
- **典型场合**：启动仪式、开幕式等活动的特定环节
- **怎么做出来的**：前半程（需求分析、架构与计算核心、UI 实现，直至选定运行模式）由**腾讯 WorkBuddy 调用 Space-bunny 模型**完成；后半程（QA 复测剩余 3 条 P2 的修复、验收销项、V1.0.1 归档交付）由 **Step5-Preview** 完成——一个非开发者的真实工作念头，加两段 AI 工程协作，落成这个零依赖、可离线双击使用的工具。

## 1. 这是什么

一个**双击就能打开的本地小工具**：你输入 LED 大屏的物理尺寸（比如 14 米 × 4 米），它告诉你

- 这块屏的**真实比例**是多少（精确到小数，不是"大概 21:9"）
- 它的**最简整数比**是多少（比如 7:2）
- 如果你要做一段视频，**该用多大的分辨率**（比如 4900×1400），以及**误差有多大**
- 画面和屏幕比例对不上时，**该裁切还是该留黑边**，各要多少像素

所有计算都在你自己的浏览器里完成，**不上传任何数据、不连任何服务器**。

### 给谁用

| 角色 | 你关心的是 |
| --- | --- |
| 视频后期 / 剪辑 | 视频文件的分辨率该做成多少、比例误差多少 |
| 活动影像 / 直播导播 | 现场屏的真实比例、给播放器的画面尺寸 |
| 舞台视觉 / MG 动画 | 异形比例下的整数倍画布、精确拼装尺寸 |
| LED 屏搭建 / 现场技术 | 屏的实际尺寸换算、控制系统能吃下的分辨率 |
| 客户对接 / 项目统筹 | 一份可以直接复制发给客户和现场的参数说明 |

## 4. 逐步操作指引

### 第 1 步：填物理尺寸

1. 看左栏最上面「**屏幕尺寸**」这一块，有两个输入框：左边是宽，右边是高。
2. **点进左边那个框**，把屏的宽度打进去（比如 `14`）。右边那个框打高度（比如 `4`）。
3. 框的右边有个小字，是**当前单位**（默认是 `m` 米）。
4. **单位不对怎么办**：点页面最上面右上角的 `m` / `cm` / `mm` 三个按钮之一切换。
   - 切完之后，**框里的数字会自动换算**（14 m 会变成 1400 cm）。
   - **重要**：换单位只改显示值，屏的实际尺寸和比例**不会变**。14 m 和 1400 cm 是同一块屏。
5. **看到什么算成功**：右栏出现一个大大的比例数字，比如 `3.5000 : 1`。

**不想手打数字？** 每个框右边有 `−` 和 `+` 两个小按钮，点一下加减一格（m 单位一格 0.1，cm 一格 1，mm 一格 10）。也可以把光标放在框里按键盘 **↑ / ↓** 键，按住 **Shift** 是 10 倍步长。

**填错了会怎样**：框下面会出红字提示，比如「尺寸必须是有效数字（最多一位小数点）」「尺寸必须大于 0」。按提示改就行。

**顺手两个按钮**：
- 「**宽高互换**」——把宽和高的数字对调（比例会跟着反过来）
- 「**恢复默认值**」——一键回到初始状态（14 m × 4 m、目标比例来源=屏幕实际比例、模式=按宽度、目标宽 1920 / 高 1080）；**整数倍模式下的自定义整数比和两个上限也一并复位**（上限清空、比例回到默认 `65:36`），不会留下上一次的残留值

---

### 第 2 步：看比例结果

填完尺寸，右栏顶部就是结果。盯住三处：

**① 大比例数字**（`ratio-value`）

```
3.5000 : 1
```

- 冒号右边恒为 `1`，冒号左边是比例值
- **这个数字是权威结果**，来自你的物理尺寸，谁也改不了它
- 大数字固定保留 4 位小数（`3.5000`）；而下面表格里的「实际比例」那行会去掉末尾多余的零（`3.5 : 1`）—— 同一个值，两种写法

**② 大数字后面的括号**（`ratio-suffix`）

- `（整数比 7:2）` —— 说明这块屏能精确写成 7:2，**这是精确值**
- `（约化值）` —— 说明写不成整数比，下面会另起一行给近似值

**③ 可能出现的「约化值（近似）」那一行**（`approx-line`）

比如 `约化值（近似） 25946:9545 · 相对误差 0.0000%`（输入 2.7182818 m × 1 m 时）。

> 这个误差百分比显示成 `0.0000%` 是正常的：它表示"小到可以忽略"，不是"算错了"。真正要紧的是那个**整数比本身**——它带「（近似）」标记，说明这个比例**没有精确的整数比表示**。

> **近似值永远单列一行，永远带「近似」二字，绝不跟精确值混在一起。**
> 看到「近似」就说明：这个比例没法用整数比精确表示，下面那个数只是很接近，不是精确值。

**④ 右栏右上角的徽标**

| 徽标 | 含义 |
| --- | --- |
| `✓ 严格匹配` | 比例和画布都精确，没有误差 |
| `Δ 取整误差` | 比例没问题，但画布尺寸存在取整误差 |
| `▲ 非标准比例` | 这个比例不在常见标准画幅里（超出容差） |
| `! 需现场确认` | 目标比例还没确定 |
| `! 输入有误` | 尺寸填错了，先改尺寸 |

> **注意判定顺序**：「非标准比例」优先于「严格匹配」。所以一块 14m×4m 的屏，即使宽度刚好整除，也会被标成「非标准比例」—— 这是**故意的**，因为它要提醒你"这不是 21:9"。

---

### 第 3 步：选目标比例

左栏第二块「**目标比例来源**」，三个按钮：

| 按钮 | 什么时候用 |
| --- | --- |
| **以屏幕实际比例**（默认） | 你要做一段和屏**完全贴合**的视频 |
| **以选中标准比例** | 你要做 16:9 / 21:9 这类标准画幅，但屏可能不是那个比例 |
| **自定义** | 你有个自己的整数比，比如 `65:36` |

**选「以选中标准比例」怎么操作**：
1. 点「以选中标准比例」按钮。
2. 按钮下面会展开一个比例库列表（`standard-list`），16 条，包括 16:9、16:10、4:3、3:2、1:1、9:16、4:5、**21:9（俗称）**、32:9、2.35:1、2.39:1、2.40:1、3440×1440、3840×1646、3840×2160、1920×1080。
3. **点其中一条**，选中项会高亮。

> **⚠️ 21:9 那条要特别看一眼**：
> 列表里它显示的是「**21:9（俗称）**」，右边的小字写的是 **`7:3`**。
> 这是因为 21:9 是行业里的叫法，它的严格数学比例其实是 7:3 ≈ 2.3333。
> 工具**不会**用这个俗称去改写你算出来的真实比例，只在你自己主动选它的时候才生效。

**选「自定义」怎么操作**：
1. 点「自定义」按钮。
2. 展开的输入框里填**整数比例**，格式是 `a:b`，中间一个半角冒号，两边都是正整数。比如 `65:36`。
3. 填对了不会报错；填错了（比如 `65/36`、`65:`、`a:b`）框下面会红字提示「请输入形如 65:36 的正整数比例」。

---

### 第 4 步：换算画布

左栏第三块「**目标画布模式**」，四个按钮 —— **这是本工具的核心，四种模式怎么用见第 5 节**。

不管选哪种，右栏都会给你一份「**候选分辨率与匹配度**」列表，把能算的方案都列出来，当前选中的那个标着「（当前）」。

---

### 第 5 步：复制参数

右栏最下面有两个大按钮：

**「复制分辨率」**
- 复制结果就是一行纯文本，比如 `4900×1400`
- 用的连接符是 `×`（乘号），**不带千分位逗号** —— 直接粘到任何地方都不会出问题

**「复制完整参数」**
- 复制一整段说明文字，内容包括：屏幕实际尺寸、实际比例、最简整数比例、目标比例来源、目标画布分辨率、输出比例、**宽高比相对误差**、**像素尺寸误差**、是否严格匹配、等比适配方案，最后附上「以下参数需现场确认（本工具不推导）」和第 ②③④ 层参数（没填就写「未填写」）
- **这个就是发微信 / 发邮件给客户和现场的那个东西** —— 直接粘，不用再组织语言

**复制成功的样子**：按钮上图标变成 `✓`、文字变成「已复制」，约 1.6 秒后自动还原。
**复制失败的样子**：图标变成 `!`、文字变成「复制失败」，旁边提示「复制失败，请手动选取文本复制」。这时候就手动选中文字按 Ctrl+C。

### 第 6 步（可选）：用「演示案例」快速上手

左栏最底下有一块「**演示案例**」，点一条就自动把对应参数填进输入框，适合先摸清工具怎么用。

| 案例 | 载入后 | 你会看到 |
| --- | --- | --- |
| 14m × 4m 超宽工程屏（3.5:1） | 宽 14 / 高 4（m），目标宽 4900 | 比例 `3.5000:1`、画布 `4900×1400`、徽标「非标准比例」 |
| 21:9（7:3）目标比例 · 3840px 宽 | 宽 21 / 高 9（m），目标宽 3840 | 比例 `2.3333:1`、画布 `3840×1646`、徽标「取整误差」 |

## 5. 四种换算模式怎么用

### 模式 ①「按宽度」

**什么时候用**：播放设备、合成软件是按**宽度**定尺寸的（绝大多数情况）。

**怎么用**：
1. 点「按宽度」按钮。
2. 在展开的「**目标宽度（px）**」框里填宽度，比如 `4900`。
3. 高度由工具反算出来。

**看到什么**：
- 右栏「目标画布分辨率」显示 `4900 × 1400`
- 候选列表里「按目标宽度」那条标着「（当前）」
- 下面会写「理论高 1400.0000px」—— 这是没取整的精确值
- 如果四舍五入和"按比例误差最小"两个结果不一样，会同时列出。真实例子：目标比例 `40:29`、宽度 4900 px 时，理论高 3552.5000 px，四舍五入得 3552，而**按比例误差最小**得 3553 —— 界面会把两个都列出来：「四舍五入取整 3552px · 按比例误差最小取整 3553px」，**两个方案都给你看，不替你决定**

**举例**：屏是 14m×4m（比例 3.5），目标宽度填 4900 → 理论高正好 1400，**严格匹配，误差 0**。

### 模式 ②「按高度」

**什么时候用**：高度是硬约束的情况（按屏高整数倍拼装的场合）。

**怎么用**：
1. 点「按高度」按钮。
2. 在「**目标高度（px）**」框里填高度，比如 `1080`。
3. 宽度由工具反算。

**举例**：屏比例 3.5，目标高度填 1080 → 理论宽 3780 → 输出 `3780×1080`。

> 模式 ① 和 ② 可以**同时**算 —— 只要两个框都填了数，候选列表里两条都在，可以对比着看。

### 模式 ③「常用规格」

**什么时候用**：你要的就是一个常见标准分辨率（1080p、2K、4K……），想看看它和这块屏配不配。

**怎么用**：
1. 点「常用规格」按钮。
2. 展开的列表里点一条，共 7 条：

| 规格 | 严格比例 |
| --- | --- |
| 1920×1080 | 16:9 |
| 2560×1440 | 16:9 |
| 3440×1440 | 43:18 |
| 3840×2160 | 16:9 |
| 3840×1646 | 1920:823 |
| 4096×2160 | 256:135 |
| 5120×2160 | 64:27 |

3. 点了之后，工具会告诉你这个规格和你的目标比例差多少。

> **每个规格现在直接显示两样东西**（1.0.1 新增）：它的「**真实比例**」和「**离你这块屏差多少**」（偏差，比如 `1.7778 · 偏差 +49.2063%`）。真实比例是用像素宽高实算的，偏差是跟**屏幕实际比例**比的，跟着你填的屏幕尺寸实时刷新。你不用点进去，在这个列表里就能看到每个规格离你的屏有多远。

**看到什么**：候选列表里「常用规格」那条显示该分辨率，右边标着「（当前）」；下面有「实际像素比例」「与目标比例的宽高比误差」。误差不为 0 时，这两个数会带上黄色警示色。

> **注意**：预设的比例是**用像素宽高实算**的，不是"约等于 16:9"。所以 3440×1440 显示的是 43:18，不是 16:9 —— 这是事实，不是 bug。
>
> 另：**预设与目标比例差距大时不会弹警示条**（警示条只针对"目标比例本身是不是标准画幅"）。差距直接体现在候选列表里的「与目标比例的宽高比误差」上 —— 比如目标比例 21:9 配 1920×1080，会显示 `+23.81%`，并给出「需裁切（左右各 300.00px）」的适配建议。

### 模式 ④「整数倍」

**什么时候用**：**异形屏**（非标准比例）要做精确拼装，或者现场要求"必须是整箱整数倍"。

**怎么用**：
1. 点「整数倍」按钮。
2. 在「**自定义整数比与上限**」这一块填三样东西：
   - 左边第一个框：整数比，格式 `a:b`，比如 `65:36`
   - 右边第一个框：**最大画布宽** px（比如 `1920`）
   - 右边第二个框：**最大画布高** px（比如 `1080`）
3. 下面还有一个二选一的小按钮（求解偏好）：
   - 「**以屏高定 k**」（默认）—— 以屏高为基准算整数倍（LED 屏通常按高度整数倍拼装）
   - 「**严格落在上限内**」—— 以"宽高都不超上限"为准
4. **三个框都填了才算数**，少填一个这个模式就不参与计算。

> **切档位不会让任何一个解消失** —— 两个解恒定并列显示，详见下面的「看到什么」。

**看到什么**：候选列表里「整数倍画布」那条会**同时列出两个解**，两个解始终都在：

- **主解（标「（当前）」）= 不超上限、且比例精确的最大解**
- 卡片上会明确写出两行：
  - 「**严格落在上限内** W×H（k=…）」—— 界内解
  - 「**精确解** W×H（k=…），超出上限 30px」—— 精确整数倍解（超限时标出超出多少）
- 如果**连 1 倍都放不进上限**，界面会直接告诉你「没有任何整数倍能同时落在给定上限内」
- 如果你选的档位算出来的解超了宽，界面会补一句「所选档位的解已超宽，当前采用不超限的解」

**举例**：整数比 `65:36`，上限 1920×1080 →
- 主解（当前）：**1885×1044**（k=29，不超上限，比例精确命中 65:36）
- 卡片上并列写：「严格落在上限内 1885 × 1044（k=29）」+「精确解 1950 × 1080（k=30），超出上限 30px」

> **为什么两个解都在**：需求同时要两件事 ——「优先找**不超限**且比例精确的最大解」（主解满足）和「**必须提供**精确整数倍尺寸 1950×1080」（并列解满足）。只给一个就必然满足不了另一条，所以两个恒定并列，谁也不藏。
>
> **切「以屏高定 k」和「严格落在上限内」两个档位，两个解都还在** —— 档位只影响"以哪个基准求解"，不影响"两个都给你看"。
>
> **到底用哪个**：主解不超上限、适合直接丢给播放器；精确解是整数倍拼装尺寸，适合按箱体整数倍备料。**这是要跟现场技术方确认的事**，工具两个都给你，不替你选。
>
> 另：本模式下「复制分辨率」和「复制完整参数」**都能用** —— 顶部分辨率、结果表格、复制内容、示意图是一整条链路，不会出现"看得到但复制不出来"。

## 6. 完整参数怎么用

「复制完整参数」复制出来的东西长这样（实际内容随你的输入变化）：

```
LED 屏比例换算参数
屏幕实际尺寸：14 m × 4 m
实际比例：3.5000 : 1
最简整数比例：7:2
目标比例来源：屏幕实际比例
目标画布分辨率：4900×1400
输出比例：3.5 : 1
宽高比相对误差：0
像素尺寸误差：0
是否严格匹配：是
等比适配方案：比例一致，无需裁切或补边（不建议拉伸画面）

以下参数需现场确认（本工具不推导）：
  ② LED 控制系统接收分辨率：未填写
  ③ 后期软件视频合成分辨率：未填写
  ④ 实际交付的视频文件分辨率：未填写
```

> **三个细节别看错**：
> - 「实际比例」固定 4 位小数（`3.5000`），「输出比例」会去掉末尾多余的零（`3.5`）—— 同一个值，写法不同而已。
> - 误差为 0 时显示成 `0`，**不带 % 号**（因为格式规则里 0 单独处理）；非 0 才显示成 `+0.05%` 这种带符号的形式。
> - **误差很小时不会被抹成 0** —— 比如真实误差 0.0045%，界面会如实显示成 `+0.0045%`，不会显示成 `+0.00%`。所以「徽章说取整误差、数字却显示 +0.00%」这种自相矛盾不会出现。

**建议的用法**：

1. 先把第 ②③④ 层参数**在左栏填上**（填了会自动进这段文字）
2. 点「复制完整参数」
3. 微信发给现场技术方 / 客户，或者贴进邮件、报价单、项目文档
4. 现场照着这段参数核对，**有出入以现场为准**

## 7. 四层参数为什么要分开填（★ 最容易误解的地方）

这个工具有**四层**分辨率概念。它们**不是一回事**，混在一起是所有现场事故的根源。

| 层 | 是什么 | 谁说了算 | 在工具里怎么填 |
| --- | --- | --- | --- |
| **①** | **LED 实际物理尺寸** | 搭建方 / 现场实测 | 左栏「屏幕尺寸」两个框 —— **这是主输入** |
| **②** | **LED 控制系统接收分辨率**（处理器画布尺寸） | 控制系统厂商 / 现场技术方 | 左栏「现场参数」第一个框，**手填** |
| **③** | **后期软件视频合成分辨率** | 后期制作方 | 左栏「现场参数」第二个框，**手填** |
| **④** | **实际交付的视频文件分辨率** | 后期制作方 | 左栏「现场参数」第三个框，**手填** |

### 为什么不能合并

- **物理尺寸决定的是"比例"** —— 它只能告诉你屏是几比几，**不能**告诉你原生像素是多少
- **像素分辨率由箱体数量、控制系统、播放服务器共同决定** —— 同一块 14m×4m 的屏，用不同控制器、不同箱体组合，原生分辨率可能完全不同
- **③ 和 ④ 经常不一样** —— 你的后期工程是 3840×2160，但最终交付给播放器的文件可能是 1920×1080（为了带宽或播放器限制），这很正常，但必须写清楚

### 工具的立场

- 第 ① 层：**工具算**（这是它的本职工作）
- 第 ②③④ 层：**工具一个字都不推导**，你填什么它就原样带到导出文字里，没填就写「未填写」

> 页面右栏常驻的提示原文：
> **「本工具计算的是画布比例及视频像素尺寸建议。实际交付分辨率应以 LED 控制系统、播放服务器及现场技术方提供的参数为准。」**

**这句话是认真的。** 在第 ②③④ 层确认之前，工具给的一切都只是**建议**。

## 8. 常见问题

### Q：为什么界内解和超限解同时出现？

**A**：因为需求同时要了两件互相冲突的事，两件都得满足：

- 「**优先找不超上限、且比例精确的最大解**」→ 得到界内解 `1885×1044`（k=29）
- 「**必须提供**精确整数倍尺寸 `1950×1080`」→ 得到超限解（宽度超 30px）

只给一个，就必然满足不了另一条。所以工具**两个恒定并列**，并且**切档位也不会让另一个消失**：

| 你看到的 | 是什么 | 什么时候用 |
| --- | --- | --- |
| **主解**（标「（当前）」） | 不超上限、比例精确的最大解 | 直接交付给播放器 / 合成软件 |
| **「严格落在上限内」那一行** | 界内解（不超宽高上限） | 跟主解是同一个 |
| **「精确解」那一行** | 精确整数倍尺寸，宽度超限时标注「超出上限 30px」 | 按箱体整数倍备料、现场拼装 |

**要跟现场技术方确认**：播控设备到底吃哪一个。工具不替你选。

### Q：什么时候会弹「21:9 澄清」警示条？

**A**：警示条有**两种**不同的触发情形，文案也不同：

**① 目标比例不是常见标准画幅**（超出匹配容差）→ 弹**通用提示**：写明「不属于常见标准画幅」，并给出与俗称 21:9 相差多少、**不能按 21:9 处理**。

| 目标比例 | 与严格 7:3 的偏差 | 警示条 |
| --- | --- | --- |
| 14m×4m（7:2，非标准画幅） | 50% | **弹** —— 通用提示 + 与 21:9 的偏差 |

**② 目标比例是常见标准画幅，但容易被误当成 21:9** → 弹**澄清提示**：文案明确指向「目标比例与俗称 21:9…」，写明**不能按 21:9 解读**。判据是**目标比例与严格值 7:3 的偏差在 2.5% 以内**：

| 目标比例 | 与严格 7:3 的偏差 | 警示条 |
| --- | --- | --- |
| 21:9（严格 7:3） | 0% | 不提（它就是 21:9 本身，没有歧义） |
| 3440×1440（43:18） | 2.381% | **弹** —— 澄清「不能按 21:9 解读」 |
| 16:9 | 23.81% | **不弹** |
| 4:3 | 42.86% | **不弹** |
| 1:1 | 57.14% | **不弹** |

**为什么 16:9 / 4:3 / 1:1 现在不弹**：这几个比例离 21:9 差得远（20% 以上），根本不存在"可能被误认成 21:9"的问题。以前会对它们也弹一条「与俗称 21:9 相差 23.81%，不能按 21:9 解读」—— 那跟同屏的「✓ 严格匹配」徽章自相矛盾，属于误报，现在没有了。

> 这条 2.5% 判据**跟「设置」里的匹配容差无关**，两者各管各的：容差管"算不算标准画幅"，2.5% 管"要不要提 21:9"。

### Q：为什么 14m × 4m 不是 21:9？

**A**：14 ÷ 4 = 3.5，最简整数比是 **7:2**。21:9 的严格数学比例是 7:3 ≈ 2.3333，两者差 **50%**，远超默认 0.5% 容差。

所以工具会：① 明确标「非标准比例」；② 弹警示条，写明这个比例**与俗称 21:9 差多少**、并给出**不能按 21:9 处理**的结论；③ 在常见比例匹配表的 21:9 那行标成「非标准」（偏差显示 `+50.00%`）。

**7:2 是超宽工程屏的正常比例**，比 21:9 更宽，这没什么不对，只是不能叫 21:9。

### Q：为什么 3840 × 1646 不等于 21:9？

**A**：3840 ÷ 1646 ≈ 2.332928，最简整数比是 **1920:823**。它和 7:3 ≈ 2.333333 很接近（差 **0.0174%**，在默认 0.5% 容差之内），但**并不相等**。

21:9 只是一个行业俗称，不同厂家出的"21:9"屏实际比例都略有不同（3440×1440 是 43:18 ≈ 2.3889，和 21:9 差 2.381%，**在容差之外**）。**看到"21:9"三个字，要先问清楚严格值是多少。**

### Q：物理尺寸能推出 LED 原生像素分辨率吗？

**A**：**不能。** 物理尺寸只决定比例。原生像素分辨率由 LED 箱体数量、控制系统和播放服务器共同决定，必须现场确认。

这就是为什么第 ② 层参数是手填的。

### Q：比例不符时该裁切还是留黑边？

**A**：两种都是等比适配，**工具一律不建议拉伸画面**（拉伸会让画面变形）。

具体建议（工具会自动算给你看）：

- **内容比屏幕宽** → 推荐**裁切**，裁**左右**各一半溢出部分
  - 理由：裁左右不会切掉上下字幕和台标，大屏铺满也更干净
- **内容比屏幕窄** → 推荐**左右留黑边**，保全完整画面
  - 理由：改成上下裁切会直接切掉字幕和画面下缘，代价更大

中栏示意图可以直接看出效果：切到「完整显示」看到黑边在哪，切到「铺满」看到哪里被裁。

### Q：怎么改匹配容差？

**A**：点页面右上角的「**设置**」按钮，里面有「**匹配容差百分比**」，默认 `0.5`。

- 这个值决定"多接近算标准画幅"
- **改大会更容易判成标准比例**：调大容差能让更多比例被认成标准画幅（比如 21:9 家族里的 43:18 在小容差下可能被判成"非标准"，调大后就归入标准）
- **改小更严格**
- 设置**保存在本机浏览器里**（下次打开还在，换电脑就恢复默认）
- 点设置面板外面或按 `Esc` 可以关掉面板

> 注意：这个容差**只影响"算不算标准画幅"**（徽标、匹配表的「标准」列）。
> **不影响**「是否严格匹配」—— 严格匹配永远用 1e-9 的相对误差判定，跟这个设置无关。
>
> 另：21:9 澄清警示用的是**另一套独立判据**（目标比例与严格值 7:3 的偏差是否在 2.5% 以内），**不受上面这个容差设置影响** —— 改容差不会让 43:18 的澄清提示消失。

### Q：为什么有「四舍五入取整」和「按比例误差最小取整」两个数？

**A**：因为它们**真的可能不一样**。

比如目标比例 `40:29`、宽度 4900 px：理论高是 3552.5000 px，四舍五入得 3552，但 3553 让输出比例更贴近目标 —— 所以工具**两个都列出来**，让你自己看代价，**不替你悄悄决定**。

> 这种差异**只在极少数情况下出现**。常见的 16:9、21:9、65:36 等比例，两个取整结果是一致的，界面上就只显示一个数。

### Q：为什么「宽高比相对误差」和「像素尺寸误差」要分成两行？

**A**：因为它们量的是两回事。

- **宽高比相对误差** = |输出比例 − 目标比例| ÷ 目标比例 —— 画面**形状**偏了多少
- **像素尺寸误差** = |取整后尺寸 − 理论尺寸| ÷ 理论尺寸 —— **尺寸**偏了多少像素

有的情况两个值并不相同。真实例子：目标比例 `27:1`、宽度 256 px 时，宽高比相对误差是 `5.1852%`，像素尺寸误差是 `5.4688%` —— 前者算的是"比例偏了多少"，后者算的是"尺寸偏了多少像素"，分母不同。

不过在常见比例下（16:9、21:9、7:2、65:36 等），两个值通常非常接近甚至完全相同。**混成一行看依然会误判** —— 所以工具分列两行、两套字段，各算各的。

### Q：复制出来的 `4900×1400` 为什么没有千分位逗号？

**A**：故意的。纯文本复制用 `×` 连接、不加逗号，是为了**粘到任何地方都不出错**（有些系统不认逗号，有些会把它当千位分隔符）。

界面上显示的分辨率是带千分位的（**四位数不加逗号**，所以 4900 显示成 `4900 × 1400`；五位数及以上才加，比如 38400 显示成 `38,400`），但复制出来的一定是干净格式 `4900×1400`。

### Q：输入框能不能输 `1e3` 或 `12abc`？

**A**：**不能**，会红字提示「尺寸必须是有效数字（最多一位小数点）」。

输入框只接受：正负号 + 数字 + 最多一位小数点。`1e3` 这种科学计数法会被判非法 —— 请写成 `1000`。

### Q：工具会联网吗？会传我的数据出去吗？

**A**：**完全不会。** 离线单文件版里所有代码都内嵌了，没有外链、没有 CDN、没有网络请求。所有计算在你的浏览器本地完成。

唯一的"存储"是匹配容差设置存在本机浏览器的 `localStorage` 里（只在你自己的电脑上，别的电脑看不到）。

### Q：能用手机打开吗？

**A**：可以，用方式 A 的单文件版发到手机（微信传文件也行），用手机浏览器打开。界面在 375 px 宽度下也不横向溢出，能竖屏操作。

不过**推荐还是电脑上用** —— 现场填参数、对着示意图核对，电脑更方便。

## 9. 现场使用提示

填完四层参数后，**这些项仍需要人到现场核对**：

1. **屏的实际物理尺寸** —— 量的是**可视区**还是含边框？含边框量出来的比例是错的
2. **箱体拼接的实际效果** —— 屏的物理尺寸 ÷ 箱体尺寸才是理论像素数，实际可能有偏移、拼缝
3. **LED 控制系统的接收分辨率** —— 这是第 ② 层，必须问控制系统厂商或现场技术方，**不能猜**
4. **播放服务器 / 播放软件的解码上限** —— 4K 能不能真的播出来，取决于设备
5. **内容的安全区** —— 字幕、台标、logo 在不在会被裁掉的区域里（用中栏的「九宫格」和「中心线」辅助看）
6. **最终交付文件的实际分辨率** —— 导出后用播放器或剪辑软件核对一遍，不要只信工程设置

**顺序建议**：先跟现场要第 ②③④ 层的准确值 → 填进工具 → 复制完整参数 → 发给各方确认 → 现场照着参数核。

**遇到分歧怎么办**：以**现场技术方实测的**参数为准。工具算的是几何和建议，**现场才是事实**。

### 架构铁律（改代码前先读）

2. **`app.js` 只做交互与渲染**
   - **不在 UI 里自己算比例** —— 一律调 core 的函数
   - **不在 UI 里自己约分** —— 需要整数比就用 `Core.bestRational(ratio, Core.MAX_DENOMINATOR)`
   - 裁切 / 黑边的**方向和数值一律取 core 返回的 axis 字段**，UI 不自己比较大小来猜方向
   - 唯一一处本地运算是 `relativeDiffPercent()`，它只镜像 core 已公开的误差定义（|a − b| ÷ b）用于「常用规格 vs 目标比例」的吻合度展示，不参与任何比例求值

3. **精度纪律**
   - `ratio` / `decimal` 是**权威值**，永远来自用户输入的物理尺寸，不被任何近似值覆盖
   - 近似整数比只能出现在 `nearest`，且必须带 `exact: false`
   - 任何取整都必须同时给出「误差」与「是否严格匹配」两个标志
   - **禁止因为"看起来像 21:9"这类俗称去改写真实算出来的比例**

### 常改的地方

| 想改什么 | 改哪儿 | 注意 |
| --- | --- | --- |

## 11. 已知限制

1. **物理尺寸推不出原生像素分辨率** —— 像素由箱体数量、控制系统、播放服务器决定，本工具只给比例与像素尺寸建议
2. **第 ②③④ 层参数完全手填** —— 工具不推导、不校验、不联网获取；未确认前结果仅作参考
3. **一次只算一块屏** —— 无批量多屏导入，无历史记录，无结果存档（只有匹配容差会持久化）
4. **不联网、不上传** —— 全部本地计算，因此无法自动校验分辨率是否被控制器接受
5. **输入精度上限 1/1000 mm** —— 输入的小数超过三位时，取整（量化到 1/1000 mm）引入的相对误差会**计入近似比的接受容差**（计算核心内部处理，不会把一个本来很贴切的逼近比否掉）。⚠️ 该量化误差的**具体百分比当前不会显示在界面上**（核心层有该字段，界面未渲染），所以你在屏上看不到"这次输入的量化误差是多少"——只能看到"这个比例没有精确整数比"这一事实
6. **逼近比分母上限 10000** —— 超出范围的比例只给小数权威值
7. **「整数倍」模式必须同时填宽高两个上限** —— 少填一个则该模式不参与计算
8. **复制依赖剪贴板权限** —— 隐私模式等极端环境下需退回 `execCommand`，失败时手动选取复制
9. **深色单主题** —— 没有浅色主题，也没有主题切换
10. **没有批量导出与报表** —— 一次一个结果，复制要逐次操作
11. **示意图不是 1:1 像素** —— 中栏舞台是**示意图**，比例关系准确，但绝对像素不等于实际屏体；裁切 / 黑边的具体像素数以右栏数值为准
12. **不含屏体结构信息** —— 不算箱体拼接、不算刷新率、不算色域、不算亮度
> **已在 1.0.1 修复的三项**（原 1.0.0 已知限制，现均已解决）：
> 1. ~~控件触屏命中区偏小~~ → 24 个控件命中区已扩至 ≥36×36 px，视觉尺寸不变
> 2. ~~桌面端 Tab 焦点顺序与视觉顺序不一致~~ → DOM 顺序已对齐为「输入 → 可视化 → 结果」，Tab 走位不再倒序
> 3. ~~常用规格列表不标真实比例、候选卡偏差基准易混~~ → 预设列表现显示「真实比例 + 偏差（对屏幕）」，候选卡标签更名「与目标比例的宽高比误差」，与预设偏差显式区分两个基准
