## 0. 架构影响面与依赖关系报告（先报告，后实施）

### 0.1 结论：核心计算内核无需调整

`src/core.js` 的 `UNIT_TO_MM = { m:1000, cm:10, mm:1 }` 不含 px，且被
`core.lock.json`（`dd49a782…cc26`，22 个受保护导出）双向哈希锁死。
**v1.3.0 不修改 `src/core.js`、不修改 `src/app.js`、不修改根 `index.html`、
不修改 `core.lock.json` / `desktop/core.lock.json`、不执行 `core:accept`。**

v1.2.0 的 "1 px = 1 mm" 只存在于桌面适配层（`desktop-adapter.cjs` ⑥ 号补丁模板），
因此可以在桌面层内完整替换，不触碰内核。这也是任务书 §8「优先将新功能纳入桌面专属
适配和桌面专属计算模块」的落点。

### 0.3 回退兼容的关键决策：`schemaVersion` 保持 1

`settings-store.js` 的 `normalize()` 在 `sv > SCHEMA_VERSION` 时**整体回退**。
若把 schema 升到 2，v1.2.0 回退后将读不懂 v1.3.0 写的 `settings.json`，
导致容差配置丢失 —— 违反「保留 v1.2.0 可回退状态」。

因此 **schemaVersion 恒为 1**，P 值以**可选增量字段**写入：
- 缺字段 → 视为「未配置」（`null`），不默认 P2.5；
- 非法字段 → 视为「未配置」，不整体丢弃文件；
- 写入采用「读原文件 → 合并白名单字段 → 原子写」，**保留文件中已存在的其他键**；
- 容差 `tolerancePercent` 的默认值、校验区间、`matchStandards` 调用方式**逐字不变**。

### 0.4 明确不动的项

`appId` / `APP_DIR_NAME` / 用户数据目录 / IPC 通道名与暴露接口 / Electron 安全策略
（contextIsolation、sandbox、CSP `connect-src 'none'`、`script-src 'self'`）/

根 `package-lock.json`、`VERSION` 首行）/`core.lock.json` 哈希锁。

  「px→m 恢复原始物理尺寸、不反算」。**保持 10 项总数与 CI 新鲜度门禁不变**，

## 1. 交互结构方案

### 1.1 设置区（右下角设置 → 自绘模态，沿用 `openSettingsModal`）

原「匹配容差百分比」一行**保持原样、位置不变**，其下增加第二个独立设置项：

```
┌─ 设置 ────────────────────────────────────────────┐
│ 匹配容差百分比                                     │
│ [ 0.5                                        ]     │  ← 原样，不动
│ 容差用于判定…                                      │
├───────────────────────────────────────────────────┤
│ LED 像素间距 P                       [未配置 ●]    │  ← 状态胶囊
│ 预设 [ P2.5 ▾ ]   自定义 [            ] mm        │
│ ○ P0.9  P1.25  P1.5  P1.667  P1.86                │  ← 预设快捷 chip 行
│ ○ P2    P2.5   P3     P4      P5                  │
│ 提示：仅 >0 的有限数值；未配置时禁止物理↔像素换算   │
│ ⚠ 错误行（NaN / Infinity / 0 / 负数 / 非数值）      │
├───────────────────────────────────────────────────┤
│ [关闭]                                    [确定]   │
└───────────────────────────────────────────────────┘
```

- **两个设置项完全独立**：互不读写、互不覆盖、互不影响默认值；容差的业务逻辑零改动。
- 预设与自定义「清晰可辨」：预设为可聚焦 chip（`role="radio"` + roving tabindex），
  自定义为独立输入框；选择预设会回填输入框，手动改输入框会自动取消预设选中态。
- **未配置态**：状态胶囊显示「未配置」，清空输入即回到未配置（`null` 持久化）。
- 键盘：Tab 顺序 = 容差 → 预设组（1 个 Tab 位）→ 自定义输入 → 关闭 → 确定；
  `aria-invalid` + `aria-describedby` 指向错误行；Enter 提交、Esc 关闭复用既有模态焦点锁。
- 变更即时生效：任何 P 值改动立即触发 `LedApp.update()` 与两个新结果模块重算，
  **不需要点「确定」**（与容差一致）。

### 1.2 单位切换交互（A 栏「屏幕尺寸」组）

| 切换 | 行为 |
|---|---|
| m ↔ cm ↔ mm | 沿用原有换算逻辑，物理尺寸不变 |
| 物理 → px（已配置 P） | 由 `physicalMm / P` 换算理论整数分辨率并填入输入框，标记来源「由物理尺寸换算」 |
| 物理 → px（未配置 P） | **禁止换算**；清空两个输入框，单位组下方显示明确提示「未配置 LED 像素间距 P…可直接输入真实像素数量；原始物理尺寸保持不变」，物理尺寸字段不动 |
| px 直接输入 | 作为**真实像素数量**处理，只写 `resolutionWidthPx/HeightPx`，绝不写 `physicalWidthMm/HeightMm` |
| px → m/cm/mm | **不反算、不覆盖原始物理尺寸**；恢复进入 px 前保存的 `physicalWidthMm/HeightMm` 显示值 |
| P 值变更（px 模式） | 若 px 值来自「由物理尺寸换算」→ 重新换算；若来自「直接输入」→ **原样保留，不篡改** |

### 1.3 结果区（C 栏 `.result-body` 末尾，两个默认折叠模块）

为避免「首屏拥挤 / 滚动卡顿」，两个新模块用原生 `<details>` 折叠，**默认关闭**，
只在结果正文末尾各占 1 行标题；展开后才渲染表格。不新增吸顶/吸底层，
不干预三层 sticky 与锚点条逻辑。

```
… 既有候选卡 / 匹配表 / 结果表 / 说明 / FAQ …
▸ LED 原生分辨率估算（理论 P 值估算）        [展开]
▸ 箱体 / 模组规格核验（箱体像素矩阵计算）    [展开]
```

每个模块内部固定三段：① 状态/来源条 ② 输入摘要 ③ 结果表。
展开态用 `requestAnimationFrame` 合并刷新，输入用事件委托，避免逐字符重排整栏。

## 2. 计算结果布局方案

### 2.1 模块 A · LED 原生分辨率估算

**来源标注（常驻，不可折叠）**：`理论 P 值估算 — 基于物理尺寸与全局 P 值，非控制器确认分辨率`

| 行 | 字段 | 示例（14000×4000 mm / P2.5） | 示例（P1.86） |
|---|---|---|---|
| 输入摘要 | 屏幕物理宽 × 高 | 14000 × 4000 mm | 14000 × 4000 mm |
| 输入摘要 | 当前采用的 P 值 | P2.5（2.5 mm） | P1.86（1.86 mm） |
| 1 | 理论水平像素数量（连续值） | 5600.000000 px | 7526.881720 px |
| 2 | 理论垂直像素数量（连续值） | 1600.000000 px | 2150.537634 px |
| 3 | 理论整数分辨率估算 | 5600 × 1600 px | 7527 × 2151 px |
| 4 | 理论总像素数量 | 8,960,000 px（整数估算 8,960,000 px） | 16,188,172.0 px（整数估算 16,190,577 px） |
| 5 | 实际宽高比 | 3.500000 : 1（7:2） | 3.500000 : 1（7:2） |
| 6 | 整数化误差 | 宽 0.000000 px / 高 0.000000 px（0.0000%） | 宽 +0.118280 px / 高 +0.462366 px（相对误差分别列出） |
| 7 | 数据语义 | 物理尺寸 ↔ 像素分辨率已分离 | 同左 |

规则：
- 连续值**不丢弃小数**，保留 6 位小数展示；内部保留完整 IEEE-754 值。
- 整数估算采用 `Math.round`（正数即四舍五入，0.5 向上），并显式给出
  `integerWidthPx − theoreticalWidthPx` 的**带符号误差**与相对误差百分比。
- 误差不为 0 时高亮显示并给出「估算值不能很好满足整数分辨率约束」提示，
  **不静默修正**。
- 未配置 P / 当前为 px 输入模式 / 物理尺寸非法 → 显示明确的不可用原因，不出数字。

### 2.2 模块 B · 箱体 / 模组规格核验

**来源标注（常驻）**：`箱体像素矩阵计算 — 由单箱体像素数与拼装数量得出，与理论估算分列`

输入 6 字段：单箱体宽(mm)、高(mm)、水平像素数、垂直像素数、横向数量、纵向数量。

| 分组 | 行 | 说明 |
|---|---|---|
| 输出 | 实际拼接总宽度 / 总高度 | `cabinetW × cols`、`cabinetH × rows`（mm） |
| 输出 | 水平方向总像素 / 垂直方向总像素 | `cabinetPxW × cols`、`cabinetPxH × rows` |
| 输出 | 实际拼接分辨率 | `Wpx × Hpx` |
| 输出 | 实际拼接比例 | 由像素矩阵得出 |
| 输出 | 理论比例 | 由 P 值理论估算得出（未配置 P 时为「不可用」） |
| 差异 | 与 P 值理论估算差异 | Δ宽px / Δ高px / Δ总宽mm / Δ总高mm / Δ比例 / 相对偏差% |
| 校验 | 一致性提示 | 「完全匹配」「轻微差异」「箱体数量错误」「像素矩阵非法」「尺寸与屏幕物理尺寸不一致」 |

**两列来源永不合并**：左列固定标签「理论 P 值估算」，右列固定标签「箱体像素矩阵计算」，
差异行单列第三块。任何一行都不会只给一个无来源的数字。

### 2.3 与既有结果体系的联动边界

- 既有 `#ratio-value` / 最简整数比 / 匹配表 / 候选画布 / 复制完整参数
  **全部保持 v1.2.0 输出**，不注入估算分辨率。
- 画布建议不因 P 值而变化，不把理论估算伪装成控制器输入分辨率；
  「复制完整参数」第 ②③④ 层现场参数字段逐字不变。
- FAQ 中「物理尺寸能推出原生像素分辨率吗？不能」在桌面副本追加一句
  「v1.3.0 的 P 值估算仅为理论值，非已确认分辨率」（HTML 版不改）。

## 3. 数据模型

新增桌面专属状态（纯模块 `LedPitch.state`，**与 `LedApp.state` 分离**）：

```
physicalWidthMm      : number|null   // 仅由 m/cm/mm 输入写入
physicalHeightMm     : number|null   // 仅由 m/cm/mm 输入写入
resolutionWidthPx    : number|null   // 仅由 px 输入写入
resolutionHeightPx   : number|null   // 仅由 px 输入写入
pixelPitchMm         : number|null   // null = 未配置，绝不默认 P2.5
activeUnit           : 'm'|'cm'|'mm'|'px'
pxOrigin             : 'converted'|'direct'|null
cabinet              : { widthMm, heightMm, pixelsX, pixelsY, cols, rows }
notice               : string        // 未配置 P / 非法输入等明确提示
```

`LedApp.state.widthMm/heightMm` 保留为 v1.2.0 的**无量纲比例载体**（app.js 全部下游
计算只依赖其宽高比），在 px 模式下它承载像素数用于比例计算；**它不是物理尺寸**，
所有 P 相关计算只从上述 `physicalWidthMm/HeightMm` 取值。`readDimensions()` 返回对象
同时附带 `physicalWidthMm / physicalHeightMm / resolutionWidthPx / resolutionHeightPx /
pixelPitchMm / activeUnit / dimensionSemantic`，供桌面层显式区分语义。

## 4. 换算与取整规则（唯一口径）

```
pixelWidth  = physicalWidthMm  / pixelPitchMm
pixelHeight = physicalHeightMm / pixelPitchMm
integerWidthPx  = Math.round(pixelWidth)      // 正数四舍五入，0.5 向上
integerHeightPx = Math.round(pixelHeight)
totalPixelsTheoretical = pixelWidth * pixelHeight
totalPixelsInteger     = integerWidthPx * integerHeightPx
roundingErrorPx = integerWidthPx - pixelWidth   （高同理，带符号）
aspectRatio     = physicalWidthMm / physicalHeightMm
```

- P 值合法域：`Number.isFinite(v) && v > 0`；拒绝 NaN / ±Infinity / 0 / 负数 / 非数值串。
- P 值以 `Number` 原值存储，最多 6 位小数输入；展示用去尾零字符串，**不对存储值取整理**。
- 未配置 P 时禁止一切依赖 P 的物理↔像素换算，并给出明确提示。
- m/cm/mm 沿用 `UNIT_TO_MM`（1000 / 10 / 1），px 不参与该表。
