## 一、core.js 的 22 个受保护导出

| # | 导出 | 语义 |

| 4 | `computeRatio` | 真实宽高比 + 最简整数比 + 精确/近似判定 |
| 5 | `gcd` | 最大公约数 |

| 7 | `matchStandards` | 标准比例匹配（容差内判定） |
| 8 | `STANDARDS` | 标准比例库（16 条，21:9 含俗称标注） |
| 9 | `canvasFromWidth` | 按宽度换算画布 |
| 10 | `canvasFromHeight` | 按高度换算画布 |
| 11 | `fitAdvice` | 等比适配建议（exact / crop / letterbox，**绝不含拉伸**） |

| 13 | `PRESETS` | 常用规格（7 条） |

| 17 | `roundErrorPercent` | 取整误差百分比 |

| 20 | `APPROX_REL_TOL` | 近似匹配容差（1e-6） |
| 21 | `MAX_DENOMINATOR` | 逼近分母上限（10000） |
| 22 | `DEFAULT_TOLERANCE_PERCENT` | 默认匹配容差（0.5） |

**🔒 core.js 整体 SHA-256 锁定**：
```
dd49a7829618f77da4c07baafd4e5d6f08e23f8577d074c5500d006a011bcc26
```
不一致 → `npm run sync` 失败 → 构建阻断。更新必须由项目负责人确认后执行 `npm run core:accept`。

## 二、app.js 的 8 处受保护业务口径

**机器闸**：`test/guard-redlines.mjs` 的 A-01~A-08（基于**内容**而非行号）。

| 编号 | 标识符 | 当前值 | 为什么不能动 |
|---|---|---|---|
| **A-01** | `NEAR_21_9_PERCENT` | `2.5` | 3440×1440 与真实 21:9 相差 2.3810%，阈值 2.5 恰好把这类「俗称 21:9」识别出来。改动会让误报与漏报同时改变 |
| **A-02** | `DEFAULT_CUSTOM_CANVAS_RATIO` | `'65:36'` | 现场常用大屏比例默认值，改动会静默改变所有新用户的默认档位 |
| **A-03** | `customCanvasPrefer` | `'bounds'` | 整数倍求解默认档位（界内解优先），切换会改变双解候选的主次呈现 |
| **A-04** | `UNIT_SPEC` | m/cm/mm 三档步长与小数位 | 决定输入校验口径，改动会让同一物理尺寸产生不同可输入值 |
| **A-05** | `SITE_FIELDS` | ②③④ 三字段 | 四层参数模型的业务骨架 —— ②③④ 必须是手填事实，工具一个字都不推导 |
| **A-06** | `relativeDiffPercent` | core 未导出的误差镜像 | 与 core 口径必须一致，否则会出现两套误差数字 |
| **A-07** | `fmtErrorPercent` | 走 core 的误差格式化 | 保证「非零误差不显示为 0」这条自相矛盾防护在表现层同样成立 |
| **A-08** | `renderBadge` | 五态 + 判定优先级 | 优先级为 非标准比例 > 取整误差 > 严格匹配，改动会让同一结果给出不同结论标签 |

## 三、桌面侧的等价约束（渲染层）

| 约束 | 说明 |
|---|---|
| **UI 层零计算** | 渲染进程、`desktop-ui.js`、主进程**一律不得**出现 `gcd` / `bestRational` / `computeRatio` / `approx` / `denominator` / `toMm` / `parseDimension` 的自行实现。业务数值只能来自 `Core.*` 成员访问 |
| **主进程零业务计算** | `main/` 下上述标识符 grep 命中数必须为 **0**（SEC-01） |
| **复制载荷格式** | `宽×高` 用 U+00D7（×）、**不带千分位**；完整参数文本字段与顺序逐字不变 |
| **21:9 阈值独立于容差** | `NEAR_21_9_PERCENT` 是常量，不随匹配容差变化 |
| **双解并列** | 整数倍画布的「界内解」与「精确解」必须同时展示，不得伪装无解 |
| **取整双值并列** | 四舍五入建议值与最小误差值必须同时展示 |
| **适配语义** | 只允许 exact / crop / letterbox，**绝不提供拉伸** |

## 四、修改红线时必须提交的三件套

1. **变更原因** —— 为什么要改
2. **影响面分析** —— 影响哪些行为、哪些测试
3. **回归测试** —— 新增或修改的用例

三件套缺一不可，且须**项目负责人确认**。
